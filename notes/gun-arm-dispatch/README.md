# The hero's weapon-state arms, read off the switch that selects them

13 shared-bank names, derived from control flow rather than from a render.

## Why these resisted everything else

`notes/shared-bank-geometry/` named 52 offsets from cross-stage consensus:
the same picture is called walk-left frame 14 by CAPSULE, CAVES and PRISON
independently, and unanimity across two or more stages settles it.

Two groups had no such consensus to form. The forked arms around `0x33F2` and
`0x35B4` have one named drawer between them; the single-pixel dots at
`0x5BF8..0x5C1C` have none, and rendering a one-pixel dot at an unknown
palette tells you it is a dot.

They did not need a render. The code says what they are.

## The dispatch

Both directions of the armed hero are a switch on `[0x0A]`, one arm polygon
per case:

```
jne [0x0A], 0x02, <next case>
video type=0, offset=CV_33F2, ...      <- the arm for case 2
jg  [0x06], [0x30], <ret>              <- only while charge <= threshold
mov [0xF8], [0x31]
and [0xF8], 0x0004                     <- and a timer bit is set
je  [0xF8], 0x00, <ret>
video type=0, offset=CV_5C0C, ...      <- the dot, only while blinking
```

A case number is not an index anyone assigned to the art — it is the value the
VM compares against. Reading it is not "naming from the index": NAMING.md §2
bars the *disassembler's* encounter order, which carries no meaning. This
carries the machine's.

    $ python3 notes/gun-arm-dispatch/arm_case_table.py
    switch starting at CV_347C (6 files)     switch starting at CV_35B4 (6 files)
      case 1: CV_347C  + CV_5BF8               case 1: CV_35B4
      case 2: CV_33F2  + CV_5C0C               case 2: CV_35D0
      case 3: CV_3420  + CV_5C14               case 3: CV_35F8
      case 4: CV_344E  + CV_5C1C               case 4: CV_3614  + CV_5C8C

Both tables are recovered independently from six files (two ports × PRISON,
CAVES, CAPSULE) and agree everywhere; the probe exits 1 on disagreement,
because one offset serving two cases would break the naming.

## The two things that needed real evidence

**Case 4 is the `else`, and calling it 4 is a measurement.** In the three
stages that have this dispatch the only literals ever written to `[0x0A]` are
0, 1, 3 and 4, so the default branch handles exactly 4. TANK and LAKE write
large values to the same variable and have no such dispatch — `[0x0A]` is
reused per stage, which is why no whole-game alias for it would be right.

**Direction.** The obvious test fails, and the control is what caught it: the
two switches' art are not mirror images — but neither are the *known* LEFT and
RIGHT walk arms at the same frame index. This game draws separate poses per
direction, so a mirror test cannot assign direction here at all. The test was
invalid, not the hypothesis.

The entry site assigns it, twice over and independently per switch:

| switch | evidence |
|---|---|
| `CV_35B4` | entered from blocks that have just drawn `HERO_STAND_LEFT_ARM`, `CV_331A`, `CV_332A`, `CV_3332`, `CV_333A`, `CV_3342` — the walk-left arms; callers 70:10 LEFT-named; cases 2 and 3 already carry the earned `HERO_GUN_ARM_POSE_LEFT_CASE_02` / `_CASE_03` |
| `CV_347C` | 16 entry sites, **15 of which have just drawn a `HERO_WALK_RIGHT_BODY_F*`** and none a left-facing one |

The right-hand column of that table is names this project earned by other
routes — the walk-right bodies came from four-way cross-stage consensus in the
previous pass — so the two results check each other.

## "Charge blink" is in the opcodes

The dot is drawn only when the charge `[0x06]` is at or below a threshold
`[0x30]` **and** bit 2 of a timer `[0x31]` is set. That is a low-charge blink
stated in instructions. It is corroborated by two names earned in different
stages on a sibling dot drawn under the identical guard:
`CAPSULE_HERO_AIM_HOLD_RIGHT_DRAW_LOW_CHARGE_BLINK` and
`HERO_CROUCH_ARMED_RIGHT_FRAME_CHARGE_BLINK`.

## The 13

`gun_arm_cases.map`, generated by `--proposals` rather than typed, applied with
`notes/shared-bank-naming/apply_bank_names.py --map`:

    HERO_GUN_ARM_RIGHT_CASE_01..04        and each one's _CHARGE_BLINK dot
    HERO_GUN_ARM_LEFT_CASE_01..04         and case 4's _CHARGE_BLINK dot

Both index runs are complete, 1 to 4. The left switch draws a dot only in case
4; that asymmetry is what the code does, and inventing left dots for cases 1-3
to make the two sides match would be inventing.

Verified: `make test` 29/29 and 29/29; `bank_name_offset_consistent.py --map
gun_arm_cases.map` reports all 13 defined at the offset their key encoded, and
0 actionable duplicate names. 287 offset keys remain.

## A defect in the probe, recorded

The direction detector first looked only at the switch's **head** symbol.
Case 1 is an unnamed `LABEL_<hex>` in both switches, so it found nothing and
reported the left switch's direction as undetermined — while the evidence, an
earned label reading `LEFT` in plain text, sat two lines away on case 2. It
now scans every case. A detector that reads only the first row of a table will
miss anything the table records later.
